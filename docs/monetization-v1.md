# پیکربندی پرداخت تحصیل‌یار (نسخه اول)

## متغیرهای محیطی سمت سرور

این متغیرها را فقط در بخش Secrets / Environment Variables محیط سرور (از جمله Manus Preview) ثبت کنید؛ هیچ‌کدام نباید با پیشوند `VITE_` در اختیار مرورگر قرار بگیرند.

| متغیر | کاربرد |
|---|---|
| `ZARINPAL_MERCHANT_ID` | شناسه پذیرنده زرین‌پال |
| `APP_BASE_URL` | آدرس عمومی برنامه، بدون اسلش انتهایی؛ مانند `https://example.com` |
| `ZARINPAL_API_BASE_URL` | آدرس API نسخه ۴؛ پیش‌فرض `https://payment.zarinpal.com/pg/v4` |
| `ZARINPAL_PAYMENT_PAGE_BASE_URL` | آدرس صفحه پرداخت؛ پیش‌فرض `https://payment.zarinpal.com/pg/StartPay` |

برای محیط آزمایشی، هر دو آدرس API و صفحه پرداخت را مطابق مقادیر رسمی sandbox حساب زرین‌پال تنظیم کنید. شناسه پذیرنده آزمایشی را با شناسه محیط واقعی جابه‌جا نکنید.

## مبالغ

مبالغ در دیتابیس و درخواست API بر حسب ریال ثبت می‌شوند:
- پلاس ماهانه: ۱٬۴۹۰٬۰۰۰ ریال (۱۴۹٬۰۰۰ تومان)
- پلاس سه‌ماهه: ۳٬۹۹۰٬۰۰۰ ریال (۳۹۹٬۰۰۰ تومان)

مبلغ از رکورد فعال طرح در دیتابیس خوانده می‌شود؛ سرور مبلغ ارسالی از مرورگر را مبنای پرداخت قرار نمی‌دهد.

## مسیر پرداخت

1. کاربر وارد حساب می‌شود و از procedure احراز هویت‌شده `billing.checkout` یکی از دو طرح را انتخاب می‌کند.
2. رکورد پرداخت با وضعیت `pending` ساخته و درخواست پرداخت از API زرین‌پال ایجاد می‌شود.
3. زرین‌پال کاربر را به `/api/payments/zarinpal/callback` بازمی‌گرداند.
4. سرور با مبلغ ذخیره‌شده در دیتابیس، درخواست verify می‌فرستد.
5. فقط پاسخ موفق `code = 100` اشتراک را فعال می‌کند. پاسخ `101` به‌تنهایی باعث فعال‌سازی نمی‌شود.
6. ثبت موفقیت پرداخت، اتصال پرداخت به اشتراک، تمدید اشتراک موجود و بستن اعتبار رایگان همان ماه در یک تراکنش دیتابیس انجام می‌شود.

## قبل از فعال‌سازی واقعی

- مقادیر Secrets و callback URL باید در محیط مقصد تنظیم شوند.
- migration درآمدزایی باید روی دیتابیس همان محیط اجرا شده باشد.
- یک پرداخت آزمایشی موفق، ناموفق، لغوشده و callback تکراری باید بررسی شود.
- تا پیش از تست end-to-end با پذیرنده متعلق به پروژه، پرداخت واقعی را فعال نکنید.
